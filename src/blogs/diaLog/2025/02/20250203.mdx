# MDX 에 대한 기록 및 생각

MD를 처음 배웠을 때, 이런 문법을 어디다 쓰지? 라는 생각이 들었다.
노션을 처음 접했을때의 그런 기분은 되게 신선했다 나는 항상 WYSIWYG 만 사용해왔기 때문이다.
Markdown을 처음 접했을 때는 불편했지만, 지금은 꽤 익숙해졌다. 
다만 문서 작성시 기본적인 마크업 외에 좀 더 복잡한 구조나 인터랙티브한 요소가 필요할 때는 한계가 있다. 
예를 들자면 폰트 크기를 자유롭게 조절하거나, 원하는 색상을 적용하거나, 특정 문장만 폰트를 변경하는 것이 어렵다.
"#" 란 요소는 크기 조절보단 제목을 만든다는 느낌이 강하고, 색상은 HTML 태그를 연결해야하지만, 그러면 너무 복잡해진다.

MDX는 내가 처음 봤을때 느끼기론 좀 투머치 하지 않나 하고 생각했다.
MDX는 Markdown 안에서 React 컴포넌트를 사용할 수 있게 해주는 포맷이다.
이것은 Markdown의 한계를 극복하고, 더욱 다양한 형태의 문서를 작성할 수 있게 해준다.
(단, MDX는 일반 Markdown과 달리 React 환경에서 변환 과정을 거쳐야 제대로 볼 수 있다.)

## MDX 문법

1. JSX 컴포넌트 사용

```jsx
import { Counter } from '@/components/Counter';

<Counter />
```

2. JS 코드 실행 가능

```jsx
const name = 'MDX';

# Hello, {name}!
```

3. Props 전달

```jsx
import { Card } from '@/components/Card';

<Card title="MDX" color="blue">
  MDX is awesome!
</Card>
```

4. 로컬 변수와 표현식 사용

```jsx
export const metadata = {
  author: "John Doe",
  date: "2025-02-03"
}

# {metadata.author}님의 글
작성일 : {new Date(metadata.date).toLocaleDateString()}
```

## MDX 장점

- 컴포넌트 재사용성: Markdown 문법을 사용하면서 React 컴포넌트를 재사용할 수 있다.

- 동적인 콘텐츠: JS 코드를 사용할 수 있어서 동적인 콘텐츠를 쉽게 작성할 수 있다.

- 스타일링 유연성: 리액트의 스타일링 솔루션을 그대로 사용할 수 있어서 스타일링이 편리하다.


## 결론

MDX는 Markdown의 한계를 극복하고, 더욱 다양한 형태의 문서를 작성할 수 있게 해준다.
기술 블로그나 문서화에 유용하게 사용할 수 있을 것 같다.
